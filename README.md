# ST73 // LCD

把一张图片送进 **STM32F103C8 + ST7735** 的彩屏。

只有这一件事。不做 GIF，不做视频，不做实时动画。

在线：<https://themarter.github.io/stm32-st7735-media/>

---

## 它怎么工作

```
图片 ──▶ 浏览器转 RGB565 ──▶ 串口(USB-TTL) ──▶ STM32 ──▶ DIO/CLK ──▶ ST7735
        (canvas, 本地完成)      115200 8-N-1     收字节    软件 SPI     亮屏
```

网页不碰引脚，它只把像素倒进串口。真正打时序的是 MCU：`PB10` 出时钟、`PB11` 出数据，一个字节 8 个时钟推上去。

## 接线

屏幕和串口是两组线，别混。

| ST7735 | STM32F103C8 | 作用 |
| --- | --- | --- |
| SCL / CLK | **PB10** | 时钟，GPIO 模拟 |
| SDA / DIO | **PB11** | 数据，GPIO 模拟 |
| DC | PB0 | 命令 / 数据 |
| RES | PB1 | 复位 |
| CS | PA7 | 片选 |
| BL / LED | PA6 | 背光 |

| USB-TTL | STM32F103C8 |
| --- | --- |
| TX | PA10（USART1_RX） |
| RX | PA9（USART1_TX） |
| GND | GND（必须共地） |

屏幕侧是 **SPI，不是 I²C**，尽管丝印写着 SCL/SDA——那是 SPI 的 CLK/DIN 被商家标成了 I²C 的名字。ST7735 这颗控制器根本没有 I²C 接口。串口 115200、8-N-1。

## 网页怎么用

1. 拖一张图进去 → 自动裁成屏幕画幅、转 RGB565。
2. 选模组尺寸和方向。
3. 点「连接串口」，选你的 CH340。连上会**自动握手**：绿灯「设备在线 · 固件 v3」才算链路通。
4. 点「发送到屏幕」。

115200 下大约 4 秒一帧，921600 下 0.5 秒。发完会等 MCU 回 3 字节确认；收不到只是提示，不影响发送。

需要 Chrome 或 Edge，且页面跑在 HTTPS 或 localhost 下。

## 固件怎么用

`firmware/` 里是完整的四个文件：

| 文件 | 作用 |
| --- | --- |
| `st7735.c/.h` | ST7735 驱动，软件 SPI，流式写屏 |
| `st73_receiver.c/.h` | 串口字节 → 帧头解析 → 像素流，不缓存整帧 |
| `main_example.c` | USART1 + 环形队列 + 主循环，可直接替换工程里的 `main.c` |
| `test_receiver.c` | 主机侧自测，不需要板子 |
| `test_cross.c` | 拿网页真实产出的帧做交叉验证，不需要板子 |

Keil 工程里放法：驱动和接收器进 `my_lib/`，`main_example.c` 当作 `user/main.c`。文件名保持 `st73_receiver.c` / `st7735.c`，工程的 `.uvprojx` 不用动。

改波特率就改 `main_example.c` 顶部的 `LINK_BAUD`，网页那边也要选一样的。

**默认是 115200，不是 921600。** 软件 SPI 靠 delay 打时序，系统时钟差一点照样能出上电图案；但 USART 的波特率是拿 PCLK2 分频算出来的，工程要是没把时钟配到 72 MHz（或者用的是内部 HSI），921600 会差到收不到任何字节——症状就是「屏能亮，传图没反应」。先低速把链路确认通，再往上提。

## 烧进板子

工程是 `template.uvprojx`（Device = STM32F103C8，编译器 ARMCC V5.06）。

1. F7 编译，产物在 `Objects/template.hex`。
2. 下载，两条路任选：
   - **ST-Link（推荐）**：VCC / GND / SWDIO=PA13 / SWCLK=PA14 四根线，Keil 里 Debug 选 ST-Link，按 Load。
   - **串口 ISP**：BOOT0 拉高、BOOT1 接地，复位后用 STM32CubeProgrammer 走 USART1 下 hex，下完 BOOT0 拉回低再复位。
3. 烧完先把串口拔了，只上电看屏幕：四角彩块 + 白十字 + 底部几个小白点。这一步过了，才说明驱动和接线没问题，白点还能告诉你烧的是哪一版。

注意 PA9 既是 USART1 的 TX，也是串口 ISP 的下载线，别把下载器和 USB-TTL 同时接上去。

## 出问题按这个顺序查

**第一步：上电有没有图案**

上电后屏幕应该出现：四角四个彩色方块（红、绿、蓝、黄）+ 中间白色十字 + **底部一排小白点（几个点就是固件 v 几）**。

- 有彩块和十字，但**底部没有白点** → 烧进去的是旧固件（v2 及以前），协议对不上，重新编译下载。
- 有 → DIO/CLK/DC/RES/CS 接线和初始化都是对的，问题在后面。
- 什么都没有 → 先别管串口。查背光(BL)、共地、RES，或者模组是不是 128×160 之外的其他尺寸（那样初始化参数要改）。

**第二步：串口通不通（看握手）**

网页点「连接串口」后会自动发一次 PING：

- 显示绿点「设备在线 · 固件 v3」→ 链路通，可以直接发送。
- 显示红点「串口开了，但设备没回应」→ 按网页日志里那四条走：
  1. **换波特率**：先试 115200 再试 921600，两边必须一致
  2. **交叉接线**：USB-TTL 的 TX 接 PA10、RX 接 PA9，GND 必须共地
  3. **固件版本**：屏底部没有白点就是旧固件
  4. **串口占用**：别的串口助手没关
- 显示「设备在线 · 固件 v2 或更旧」→ 能通，但协议版本不对，重烧固件。

**第三步：图像对不对**

- 颜色是反的 → 模组是 RGB 屏不是 BGR，改 `st7735.c` 里 `madctl[]` 的 `0x08` 位。
- 画面偏移几个像素 → 模组有 offset，需要在 `LCD_SetWindow` 里加偏移量。
- 方向不对 → 网页切方向就行，不用重烧。
- 画面出来一半就停了 → 串口丢字节，降波特率（921600 → 115200）或缩短杜邦线。

## 协议

见 [`firmware/PROTOCOL.md`](firmware/PROTOCOL.md)。一句话：`A5 5A 01 W_LO W_HI H_LO H_HI ORI SUM` + `W*H*2` 字节 RGB565（高字节在前）。

## 自测

装了 gcc 就跑：

```
gcc -std=c99 -Wall -Wextra -Werror -pedantic firmware/st73_receiver.c firmware/test_receiver.c -o st73_test
./st73_test
```

32 项断言，覆盖整帧/逐字节/噪声同步/坏校验/尺寸拒收/连发两帧/半帧复位/像素逐字节一致。主机测试通过不等于屏幕能亮，显示还取决于模组版本和接线。

## 交叉验证

上面那 32 项只证明固件自己逻辑对，证明不了「网页发的东西它认」。所以还有一层：把网页真正写进串口的字节流原样存成 `frame.bin`，直接喂进 `st73_stream_feed`。

```
gcc -std=c99 -Wall -Wextra -Werror -pedantic firmware/st73_receiver.c firmware/test_cross.c -o test_cross
./test_cross frame.bin
```

128×160 一帧正好 40969 字节（9 字节头 + 40960 像素）。`frame.bin` 的抓法：在网页上选图，用串口工具把写出去的字节原样存盘。

五组场景：整块一次喂 / 逐字节喂 / 前面掺垃圾 / 校验和坏掉 / 屏幕拒收。

这层验证抓到过一个真 bug：上一帧发到一半断开时，串口里残留的像素字节可能恰好是 `A5 5A`（RGB565 的 `0x5AA5` 是很常见的灰色），它会把下一帧的真同步字一起圈进 9 字节窗口，导致整帧被丢——表现就是「点一次没反应，得再点第二次」。修法见 `f447c2b`：校验失败后在窗口内回退重扫。

## 和上一版的关系

上一版想做 GIF 和视频实时投屏，于是堆了 COBS、CRC32、16×16 tile 差分、RLE、双向 ACK、帧序列号——功能没验证通，复杂度先起来了。
